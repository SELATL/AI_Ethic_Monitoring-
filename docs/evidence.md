# 발표자료와 보관 코드의 대조

2026-09-27에 보관 파일을 읽고 집계한 결과입니다. 모델 학습·추론은 재실행하지 않았습니다. 발표자료는 Claude 보조로 작성됐다는 저장소 소유자의 설명에 따라, 구현의 단독 근거로 삼지 않았습니다.

## 자료별로 확인되는 사실

| 항목 | 확인된 내용 | README 반영 원칙 |
|---|---|---|
| 최종 모델 구조 | v1.1 앱은 편향·심각도 체크포인트와 별도 동조 체크포인트 사용 | 두 모델로 설명. 멀티태스크 헤드가 있다는 사실과 모델 인스턴스 수를 구분 |
| 모델 A 라벨 | 8개 혐오 카테고리의 합이 0보다 큰지와 욕설 신호를 조합 | 일반적인 편향 강도의 정답으로 표현하지 않음 |
| 욕설 처리 | 주석·발표는 원본 욕설 라벨 OR 정규식. 실제 코드는 `PROFANE = regex_hit.astype(int)` | 코드와 설명의 차이를 명시 |
| 전처리 버전 | 저장된 전처리 출력: 원본 18,742건 → 16,098건 | 현재 CSV를 이 코드로 생성했다고 단정하지 않음 |
| 현재 모델 A CSV | 학습 13,118 / 검증 2,811 / 테스트 2,811 = 18,740건 | 당시 발표의 테스트 규모와 일치하나, 생성 이력까지 입증하는 것은 아님 |
| 모델 A 성능 | 발표: Accuracy 88.1%, Macro Recall 0.874, Macro F1 0.845 | 당시 보고값으로 표시. 재현 수치나 모델 B 결과로 표현하지 않음 |
| 모델 B 평가 | 저장된 노트북 평가 출력은 85건. 예측 CSV도 85행 | 보고 성능의 평가 규모를 함께 표시 |
| 현재 모델 B CSV | 학습 678 / 검증 84 / 테스트 86 = 848건 | 기존 85건 평가와 구분 |
| 질문 단위 분할 | 발표와 학습 주석은 질문 단위 분할이라고 설명. 보관 전처리 코드는 행 단위 층화 분할 | 알고리즘이 질문 단위 분리를 보장한다고 쓰지 않음 |
| 현재 질문 겹침 | 현재 CSV의 `user_prompt` 문자열 기준 train/val, train/test, val/test 교집합 모두 0 | 현재 파일에서의 정확 일치 확인일 뿐, 유사 질문·템플릿 누수 검증은 아님 |
| 카테고리 표시 | 성별·지역·종교 보조 점수는 키워드 규칙으로 계산 | 학습 모델의 카테고리 확률로 소개하지 않음 |
| 입력 형식 | 앱은 `사용자: … / AI: …`; 모델 B 학습 자료는 `[유저 질문] … [AI 답변] …` | 형식 차이의 성능 영향을 검증했다고 주장하지 않음 |

## 현재 보관 데이터의 첫 어절 기준선

AI 답변이 `네,`, `네.`, `맞습니다` 중 하나로 시작하면 동조(1), 아니면 비동조(0)로 예측했습니다. 기존 학습 노트북에 있는 규칙과 동일한 기준입니다. 현재 CSV의 라벨과 비교해 이진 분류 Macro F1을 계산했습니다.

| 분할 | 표본 수 | 규칙의 Macro F1 |
|---|---:|---:|
| 학습 | 678 | 0.9838 |
| 검증 | 84 | 1.0000 |
| 테스트 | 86 | 1.0000 |

이 결과는 **모델의 동조 판별 능력을 재평가한 결과가 아닙니다.** 평가셋에서 문체 단서만으로도 정답을 맞힐 수 있다는 한계를 보여줍니다. 저장된 보고서의 “지름길 학습 없이 문맥을 이해했다”는 해석은 이 자료만으로 지지되지 않습니다.

## 라벨 체계

| 항목 | 모델 A: Unsmile 기반 | 모델 B: 동조 데이터 |
|---|---|---|
| 주 목표 | 집단 혐오·욕설 신호 분류 | 질문에 대한 답변의 동조 여부 |
| `bias_level` | 집단 혐오 신호와 욕설의 조합 | 답변의 편향 표현 수준 |
| `severity` | `{0:0, 1:1, 2:1, 3:2}` | `{0:0, 1:0, 2:1, 3:2}` |
| `sycophancy` | 전처리 코드에서 0으로 채운 placeholder | 실제 0/1 라벨 |

모델 A의 placeholder로 동조 탐지 성능을 주장하지 않습니다. 심각도 라벨은 편향 라벨에서 파생돼 있으므로 독립적인 사람의 심각도 평가를 학습한 것처럼 소개하지 않습니다.

## 남아 있는 재현 한계

- 모델 A 최종 학습의 전체 코드·설정·분할 이력을 현재 확보한 파일에서 모두 연결하지 못했습니다.
- 모델 B 보관 노트북은 `trainer` 정의 전에 평가 셀이 있고 중복 정의와 실험 셀이 있어 위에서 아래로 한 번에 실행하는 형태가 아닙니다.
- 모델 A의 문장 분류 성능과 앱의 대화쌍 입력 성능은 동일한 평가가 아닙니다.
- 모델 B의 85건 기록, 현재 86건 테스트 파일, 발표 설명을 동일 버전으로 확정할 수 없습니다.
- 초기 3클래스 결과와 v3의 4클래스 결과는 직접 성능 비교 대상으로 삼지 않습니다.
- API 응답 속도, 실서비스 처리량, 자동 차단의 효과는 측정·검증한 결과가 없습니다.

자료가 보존되지 않은 부분은 이후에 임의로 채워 과거 실험처럼 기록하지 않습니다. 이 저장소는 남아 있는 구현과 결과, 확인 가능한 한계를 함께 보존합니다.
